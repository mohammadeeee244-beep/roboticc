راهنمای نصب پروژه ثبت‌نام انجمن علمی رباتیک

این پروژه برای Google Apps Script + Google Sheets ساخته شده است. فایل‌ها را نمی‌توان مستقیماً مثل یک سایت معمولی روی GitHub Pages اجرا کرد، چون فرم ثبت‌نام و ورود مدیر به بک‌اند نیاز دارند.

۱) ساخت فایل داده
- در Google Drive یک Google Spreadsheet بسازید.
- شناسه فایل را از آدرس آن بردارید. شناسه بین /d/ و /edit قرار دارد.

۲) ساخت پروژه Apps Script
- به https://script.google.com بروید و New project بسازید.
- محتوای Code.gs را جایگزین کد پیش‌فرض کنید.
- سه فایل HTML با نام‌های دقیق index ، admin و dashboard بسازید و محتوای فایل‌های همین ZIP را در آن‌ها قرار دهید.

۳) تنظیم Script Properties
در Apps Script وارد Project Settings > Script Properties شوید و این سه مورد را اضافه کنید:
- SPREADSHEET_ID = شناسه Google Spreadsheet شما
- ADMIN_USERNAME = نام کاربری دلخواه شما
- ADMIN_PASSWORD = رمز عبور قوی و اختصاصی شما

رمز نمونه را در اختیار دیگران قرار ندهید و از رمز مهمی که جای دیگری استفاده می‌کنید استفاده نکنید.

۴) مجوزها و انتشار
- در Apps Script تابع doGet را با اجرای دستی اجرا نکنید؛ برای راه‌اندازی از Deploy استفاده کنید.
- Deploy > New deployment > نوع Web app
- Execute as: Me
- Who has access: Anyone (صفحه ثبت‌نام عمومی است؛ عملیات مدیریت با ورود سمت سرور محافظت می‌شود)
- مجوزهای درخواستی را با حساب مالک پروژه تأیید کنید.
- آدرس Web app را کپی کنید.

۵) آدرس‌ها
- سایت و فرم عمومی: آدرس Web app
- پنل ورود مدیر: آدرس Web app + ?page=admin
- داشبورد: فقط پس از ورود مدیر باز می‌شود.

۶) QR Code
در صفحه اصلی QR به‌صورت خودکار از آدرس Web App ساخته می‌شود. پس از Deploy آدرس را با گوشی اسکن کنید و آزمایش کنید. برای چاپ، تصویر QR صفحه را ذخیره کنید یا از QR ساز معتبر استفاده کنید.

۷) خروجی Excel
دکمه دانلود، فایل CSV با کدگذاری UTF-8 می‌سازد که با Excel باز می‌شود. در Excel در صورت نیاز از Save As فرمت .xlsx انتخاب کنید.

نکات امنیتی
- رمز عبور را داخل فایل‌های HTML یا JavaScript ننویسید.
- Script Properties را فقط در اختیار مالک پروژه نگه دارید.
- دسترسی به خود Spreadsheet را محدود نگه دارید.
- نشست مدیر پس از ۳۰ دقیقه منقضی می‌شود.
- این نمونه برای پروژه انجمن/دانشگاهی مناسب است؛ برای داده‌های حساس یا سامانه پرترافیک، احراز هویت حرفه‌ای و کنترل‌های امنیتی تکمیلی لازم است.
